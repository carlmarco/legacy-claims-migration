# T-SQL notes: every Postgres construct in this engine, translated

The engine targets PostgreSQL. Migration teams often target SQL Server. This maps each construct the engine actually uses (`src/Etl.Core/Merge.cs`, `Load/Loaders.cs`, the validator) to its SQL Server equivalent, and names the trap that comes with each one. These notes have **not** been executed against SQL Server, so treat them as a design reference, not as tested code.

| # | Engine (Postgres) | SQL Server equivalent | Trap |
|---|---|---|---|
| 1 | `INSERT … ON CONFLICT (key) DO UPDATE … WHERE (cols) IS DISTINCT FROM (EXCLUDED.cols)` | `MERGE target WITH (HOLDLOCK) AS t USING staging AS s ON t.key = s.key WHEN MATCHED AND EXISTS (SELECT s.cols EXCEPT SELECT t.cols) THEN UPDATE … WHEN NOT MATCHED THEN INSERT …;` | `MERGE` without `HOLDLOCK` races under concurrency, and it has a long bug history. Many teams use `UPDATE … FROM` then `INSERT … WHERE NOT EXISTS` in one transaction instead. |
| 2 | `IS DISTINCT FROM` (NULL-safe comparison) | `EXISTS (SELECT a EXCEPT SELECT b)`; SQL Server 2022+ also has `IS [NOT] DISTINCT FROM` | Plain `<>` treats NULL vs value as unknown and silently skips the update. |
| 3 | `RETURNING (xmax = 0)` to count inserts vs updates | `OUTPUT $action INTO @counts` on `MERGE` | `xmax` is a Postgres MVCC detail; `$action` is the documented T-SQL way. |
| 4 | `SELECT DISTINCT ON (key) … ORDER BY key, load_ts DESC, rec_id DESC` | `WITH r AS (SELECT *, ROW_NUMBER() OVER (PARTITION BY key ORDER BY load_ts DESC, rec_id DESC) rn FROM s) SELECT * FROM r WHERE rn = 1` | Always add a deterministic tie-breaker to the `ORDER BY`, or survivorship changes between runs. |
| 5 | Window aggregate field rules: `max(death_date) OVER (PARTITION BY key)` | Identical syntax | — |
| 6 | Binary `COPY … FROM STDIN (FORMAT BINARY)` | `SqlBulkCopy` (`BatchSize`, `SqlBulkCopyOptions.TableLock`), `BULK INSERT`, `bcp` | `SqlBulkCopy` maps columns by **ordinal** unless you add `ColumnMappings`. A reordered staging table loads silently into the wrong columns. |
| 7 | `CREATE UNLOGGED TABLE` for staging | No equivalent. Get *minimal logging* instead: `TABLOCK` into a heap or empty table under SIMPLE or BULK_LOGGED recovery, or stage in `tempdb` | `tempdb` is shared by the whole instance; a big migration can starve other workloads. |
| 8 | `CREATE TABLE … AS TABLE target WITH NO DATA` (types, no constraints) | `SELECT TOP 0 * INTO stage.x FROM dbo.target` | `SELECT INTO` copies the `IDENTITY` property; drop it, or the staging insert fails. |
| 9 | FK deferral: `DROP CONSTRAINT` → load → `ADD … NOT VALID` → `VALIDATE CONSTRAINT` | `ALTER TABLE child NOCHECK CONSTRAINT fk` → load → `ALTER TABLE child WITH CHECK CHECK CONSTRAINT fk` | If you skip `WITH CHECK`, the FK stays **untrusted** (`is_not_trusted = 1`) and the optimizer ignores it. |
| 10 | Transactional DDL: the whole merge, including `ALTER TABLE`, rolls back together | SQL Server DDL is also transactional | `TRUNCATE` is transactional in both, contrary to folklore. |
| 11 | Dry run = the same transaction ending in `ROLLBACK` | Identical | A long dry run still holds locks until rollback. |
| 12 | `text` / `varchar(n)` (n = characters) | `NVARCHAR(n)` (UTF-16 code units, up to 4000) / `NVARCHAR(MAX)`; `VARCHAR(n)` counts bytes | Length validation must count the same unit as the target. An emoji is 2 code units in `NVARCHAR`. |
| 13 | Case-sensitive comparisons by default | Collation decides; often case-**insensitive** by default | `'abc' = 'ABC'` is TRUE under a CI collation, which changes key matching (this engine upper-cases IDs, so it's safe either way). |
| 14 | `numeric(12,2)` / `date` / `timestamp` / `boolean` | `DECIMAL(12,2)` / `DATE` / `DATETIME2` / `BIT` | Avoid legacy `DATETIME`, which rounds to 1/300 of a second. |
| 15 | `jsonb` for the quarantined raw row | `NVARCHAR(MAX)` with `ISJSON()` check; SQL Server 2025 has a native `json` type | — |
| 16 | Checksum: `sum(('x' || left(md5(row_text),16))::bit(64)::bigint)` over `quote_nullable()` text | `SUM(CAST(CAST(HASHBYTES('MD5', row_text) AS BINARY(8)) AS BIGINT))`, with each column encoded `ISNULL('''' + REPLACE(CONVERT(NVARCHAR(MAX), col), '''', '''''') + '''', N'NULL')` | `CONCAT_WS` skips NULLs, so (NULL, 'x') and ('x', NULL) can collide. `QUOTENAME` returns NULL over 128 characters. `SUM` of `BIGINT` can overflow, so cast to `DECIMAL(38,0)`. |
| 17 | `ANALYZE surv` (temp tables are never auto-analyzed) | `#temp` tables get auto-created statistics; table variables (`@t`) historically estimate 1 row | Prefer `#temp` over `@table` for large intermediate sets. |
| 18 | Row-value comparison `(version, rec_id) > ($v, $r)` for the sync watermark | Not supported. Write `version > @v OR (version = @v AND rec_id > @r)` | Without the tie-breaker, rows sharing the boundary timestamp are skipped. |
| 19 | `ON CONFLICT DO UPDATE … WHERE false` still locks conflicting rows | `MERGE … WHEN MATCHED AND <no change>` doesn't update, but still takes locks | Filter unchanged rows out *before* the merge (an anti-join), so a no-op re-run is really read-only. |
| 20 | `max_wal_size` spaces out checkpoints during bulk loads | Log growth and `CHECKPOINT` behavior are governed by the recovery model and `TARGET_RECOVERY_TIME`; pre-size the log file | Autogrowth of the transaction log in small increments during a big load is a classic stall. |
